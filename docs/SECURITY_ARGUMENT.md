# HDT v2: conditional security argument and bounded verification

Status: proof sketch, not a mechanized cryptographic reduction or independent audit. Scope: single-user/local file encryption with fresh randomness, trusted endpoints and private output directory. Adversary may see and manipulate containers; replay of an entire valid container is outside scope.

## 1. Credential fusion
Let KT=HMAC(saltT,keyfile), KP=Argon2id(E(alpha,beta,gamma),saltP), PRK=HMAC(KT,KP). The keyfile consists of independent uniform random bytes; extraction of KT is assumed (public salt). In game G1, if the keyfile is unknown, replace KT by a uniform 32-byte key, paying the extractor advantage. In G2 replace HMAC(KT, KP) by uniform using ordinary PRF security, assuming KP is independent of the hidden key. If instead the keyfile is exposed, an analogous hybrid requires KP to be computationally indistinguishable from uniform conditional on adversary information, and the fixed-length HMAC swap-PRF assumption. A human-selected password does not meet that hypothesis automatically. Model offline guessing separately with attacker budget, password distribution and Argon2 cost. A malicious or correlated factor is not covered by these arguments. HKDF-Expand under independent encoded labels/file IDs/suite IDs gives computationally separated keys under PRF assumptions. No theorem claims that 64 KiB gives more than 256-bit derived keys.

## 2. Credential commitment
C=HMAC(Kc,H), where Kc and KW are expanded under distinct labels from the same PRK. An accepted header must satisfy the commitment, decrypt W under KW with H||C as AAD, and satisfy root-derived M over H||C||W. For a fixed genuine header and independently sampled wrong credential PRKs, an ideal independent 256-bit commitment matches with probability 2^-256 per candidate. Across q sampled PRKs, the ideal random-function birthday collision bound is q(q-1)/2^257. These are ideal-model bounds, not a proof of chosen-key commitment of HMAC. Ordinary PRF security with one secret key does not imply collision resistance across adversarially chosen keys. Explicit obligation: analyze F_H(PRK)=HMAC(Expand(PRK,"commit",ID,suite),H) in a chosen-key game including malicious H, and its composition with W/M. NFC-equivalent strings intentionally represent the same credential. A public C enables offline joint guesses, but W already enabled a joint verifier; no per-segment verifier. Commitment is a defense-in-depth candidate, not a proven fully committing AE scheme.

## 3. Stream authentication
Fix an honestly produced header, conditioned on fresh roots, no derived-key collision, no SHA-256 header-digest collision, and no successful AEAD forgery. Every record's index and length are authenticated in AAD and its key is derived for that index. Induction invariant after i accepted data records: their plaintext equals the first i genuine blocks, cumulative byte count matches, and short block if any is terminal. Base i=0 trivial. Step: a foreign record cannot verify under the fixed key/AAD unless it is a forgery, key collision or digest collision; a genuine record with wrong index/length fails strict parser; a valid next record is exactly the next genuine record. The final record uses a separate key, contains count and total, and must be followed by EOF. Thus no accepted proper truncation, duplication, reorder, foreign splice or append under the conditions. Whole-file replay remains possible. Publish only after final success; process crash may leave private temporary plaintext. This argument concerns logical acceptance, not OS durability or concurrent filesystem adversaries.

An informal game-hop bound is the sum of extraction/combiner/HKDF distinguishing advantages, fresh-context/key-collision probabilities, digest collision advantage, multi-key AEAD privacy/integrity advantages, MAC-forgery advantages and offline-guessing success. The chosen-key commitment term needs a separate bound for malicious-header ambiguity. No numerical concrete global bound claimed; 128-bit tags, multi-user and record counts matter. One-time zero nonce relies on fresh independent roots/IDs/salts and distinct derived keys. Do not allow retries with fixed roots or RNG rollback.

## 4. Executed finite model
verification/stream_model.py abstracts records as unforgeable tokens from one genuine stream and a second foreign stream. Chunk length domain {1,2}, maximum 3 chunks; includes empty, short and full last block. Enumerates sequences of length 0 through genuine length + 1, using genuine and foreign tokens with repetition. Exactly 78,185 sequences checked locally; only genuine sequence accepted for every case. This does not establish actual AES/HMAC security, arbitrary length state-space safety, or implementation refinement. CI reruns model and full wire fixtures. Follow-up: independently mechanize the induction and refinement, extend adversary to arbitrary malformed authenticated token fields and validate I/O fault invariants.

## 5. Remaining proof and audit obligations
Independent expert review of dual-PRF/extractor assumptions, chosen-key commitment, concrete multi-user bounds, parser refinement, Unicode normalization, allocation/resource budget, dependency CVEs and OS ACL behavior. No third-party audit commissioned or received. Cite RFC 5869, RFC 9106, RFC 8452, Backendal et al. CRYPTO 2023 (ePrint 2023/861), Albertini et al. USENIX Security 2022 (How to Abuse and Fix Authenticated Encryption Without Key Commitment).
