# MOSAIC-HDT v2 — audit remediation candidate (not a release)

This is a new format, not a silent migration of MOSAIC01. Legacy CLI remains separate. No independent audit or production approval.

## Wire format (all integers big endian)
Keyfile: MOSKEY02 (8), version u16=2, shape (9 bytes: 08 then eight 04 bytes), random key ID (16), random material (65536), SHA-256 of preceding bytes (32). Total 65603 bytes. SHA-256 detects accidental damage only. Core treats material as random bytes, not finite-field operations. Never copy key ID into the container. Keep keyfile separately from ciphertext and maintain verified offline backups.

Header H: MOSHDT02 (8), version u16=2, suite u16 (1–4 or 257–260), random file ID (16), independent saltP (32), saltT (32): 92 B. All suites fix chunk size 1048576 and Argon2id v19 t=3,p=4, output 32. Suite IDs 1,2,3,4 fix m=65536,262144,524288,1048576 KiB respectively; IDs 257–260 use the same four memory budgets, with SHA-512 commitment; no arbitrary resource parameters. Default CLI encryption suite 2 (API default 1 retained); decryption local budget defaults to 256 MiB, higher budgets must be explicitly authorized before any KDF. Unknown suite or exceeding budget rejected. Budget limits Argon2 memory, not total process memory. No explicit nonce or unused metadata key. C (32 B for suites 1–4; 64 B for 257–260), W (48), M (32) follow H; total 204 or 236 B. D=SHA256(H||C||W||M).

E is concatenation of u32be byte length and bytes of every argument, including labels. Three ordered NFC-normalized UTF-8 nonempty strings, 1..1024 bytes each; no trimming, NFKC or numeric coercion. Canonically equivalent strings intentionally match. Generation policy requires three distinct segments >=8 Unicode characters each, >=24 in total, not whitespace-only; this is not an entropy estimate. Recommend independent 128-bit locally generated random strings; generate_parameters() provides this API. Decryption does not apply generation policy.

KT=HMAC-SHA256(saltT, key material); KP=Argon2id(E(alpha,beta,gamma),saltP); PRK=HMAC-SHA256(KT,KP). HKDF-Expand(PRK,E("MOSAIC-HDT/v2",label,ID,u16be(suite),extra...),32) defines Expand; labels are ASCII. KW=Expand(PRK,"wrap",ID), Kc=Expand(PRK,"commit",ID). For suites 1–4 C=HMAC(Kc,H); for suites 257–260 C=SHA-512(E(ASCII "MOSAIC-HDT/commitment-sha512/v1",H,KW,Kc)). R=random 32 B; W=AES256-GCM-SIV(KW,zero12,R,H||C). Kh,Kd,Kf=Expand(R,"header"/"data"/"final",ID). M=HMAC(Kh,H||C||W). Compare C and M with constant-time comparison; validate C before unwrap. No separate parameter verifiers.

Data records: flag=01, index u64, plaintext length u32, ciphertext plus 16-byte tag. Index begins at zero, increments strictly; 1..1048576 bytes; no data after short block. Ki=Expand(Kd,"chunk",ID,u64be(index)); AES-256-GCM-SIV(Ki,zero12,plaintext,D||record prefix). Max 2^32-1 records. End record flag=02 and encrypted 16-byte (u64 count,u64 plaintext bytes) plus tag; AES-256-GCM-SIV(Kf,zero12,counts,D||02). Exactly one final, then EOF. Empty file has no data records. Fixed overhead 237 B for suites 1–4 or 269 B for suites 257–260; each data record adds 29 B. Ciphertext size still reveals precise plaintext length; no padding. No stored filenames or timestamps.

Each encryption generates fresh R, ID and salts; no resume or in-place rewrite, no rewrap-only feature. Zero nonce is used once per derived key under the fresh-key assumptions; any collision is bounded, not impossible. Both encrypt and decrypt write private temporary files and publish using a no-replace hard link after fsync and verification. Unsupported filesystems fail closed. Crash remnants may contain plaintext; remove only confirmed abandoned files manually, not broad glob deletion while another process is active. SSD secure erasure not guaranteed. Windows candidate creates temporary files with protected explicit current-user and SYSTEM DACL; fails closed on creation error. Requires trusted parent and supported filesystem; Windows-specific tests pending. No guarantee against administrators or endpoint compromise. Successful no-replace link is the publication commit point; post-link alias cleanup or POSIX directory fsync failure raises PublishedOutputError (complete visible output, durability/cleanup uncertain). Parent directory is fsynced on POSIX after link and alias unlink. Power-loss durability, Windows directory durability, cancellation, folder handling and desktop integration require further engineering.

## Security argument and limitations
Under the fixed 32-byte HMAC-SHA256 dual-PRF/entropy-extraction assumptions and Argon2id cost model, either unknown high-entropy factor should protect the credential keys. Three segments are a single structured password, not independent authentication factors unless independently generated. Keyfile is 524288 random bits but effective generic key-search target is at most 256 bits; tag is 128 bits and concrete multi-user/record bounds differ. Keyfile theft leaves password guessing; human-choice entropy unknown. Three uniformly independent six-digit strings give ~59.8 bits, not a guarantee. Reviewer benchmark is p=1, not suite p=4; no measured attack throughput here. Commitment is a candidate key-binding construction; HMAC collisions are possible in principle; a negative test is not a proof. C and W already enable joint offline verification after keyfile theft; no partial verifiers. R-derived data keys are intentionally independent of credentials conditional on fixed R; all credential changes affect KW/Kc and prevent access to R, not change Ki for a fixed R. Test both conditions.

Threats: attacker-controlled containers, automated decryption oracles, malformed lengths, cross-file splice, truncation, reorder, duplicate, malicious header, endpoint compromise, rollback, leaked filenames and timing, resource exhaustion. No remote service, no claim of FIPS, post-quantum security or independent audit. Distinct salts reduce reusable precomputation but not all multi-target speedups. No secure memory wipe guarantee in Python. Fail on missing AESGCMSIV; no cipher fallback. Official wheels with pinned cryptography are required in the proposed environment, runtime RFC vector checks actual backend capability. Dependency pin/hash and security advisory verification are release gates.

## Research boundary
Tensor shape is a serialization choice only. No tensor transformation enters Core. Kronecker mode products preserve rank-one differences; invertible matrices are not necessarily MDS. Research may explore fixed S-box DDT/LAT, branch bounds and cross-axis diffusion, never feed Core. CI checks static imports; not a proof against dynamic imports.
